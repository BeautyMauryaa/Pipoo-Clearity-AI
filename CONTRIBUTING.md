# Contributing to Pipoo Clearity AI

Hey! 👋 Thanks for checking out Pipoo Clearity AI.

This project is a work in progress, and contributions from students, beginners, and experienced developers are welcome. You do not need to know everything before joining in. Questions, thoughtful feedback, bug reports, documentation improvements, testing, and small UI fixes can all help.

## Before you start

- Read the [README](README.md) to understand what this repository does and how its frontend and backend are organized.
- Check the existing issues before starting work.
- For a larger change, open an issue first so we can discuss the idea and avoid duplicated effort.
- Please keep this repository focused on the career clarity web platform. It is separate from the Python desktop voice assistant that also uses the Pipoo name.

## Ways to contribute

- Report a reproducible bug.
- Suggest a feature or improvement.
- Improve documentation or setup instructions.
- Help test an existing workflow.
- Work on a focused frontend or backend improvement.

## A simple contribution workflow

1. **Choose an issue.** If there is no issue for your idea, open one and explain the problem or proposal.
2. **Fork the repository** on GitHub.
3. **Clone your fork** and create a branch for your change. Use a descriptive name, such as `docs/improve-setup` or `fix/login-validation`.
4. **Make a focused change.** Try to keep each pull request about one problem or improvement.
5. **Check your work.** Follow the relevant setup instructions in the README and run the checks that apply to your change. If you cannot run a check, mention that honestly in your pull request.
6. **Commit your changes** with a clear message.
7. **Open a pull request** against this repository's `main` branch. Explain what changed, why it helps, and how you checked it.

## Pull request checklist

Before submitting, please check that:

- [ ] The change relates to the issue or explains the problem it solves.
- [ ] Documentation is updated if the change affects setup or behavior.
- [ ] No secrets, API keys, passwords, or personal data are included.
- [ ] Relevant checks were run, or any checks you could not run are noted.
- [ ] The pull request description explains the change clearly.

## A few things to keep in mind

- Be respectful and constructive in discussions and reviews.
- If you are unsure how something works, ask. Learning together is part of the point.
- Do not include unrelated refactors in a small fix.
- Do not claim a feature or test is complete unless it has actually been checked.
- For changes that could delete data or affect authentication/security, discuss the approach in an issue before opening a pull request.

Thanks for helping make this project better. 🌱
